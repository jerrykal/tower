# Decisions

Design decisions taken while building tower, one line each: what, why, and
the alternatives. Newest last.

| # | Decision | Why | Alternatives |
| --- | --- | --- | --- |
| 1 | Packages `config`, `tmux`, `stream` and `client` beside `proto`, `towerd`, `transport`, `relay`, `loop` and `ui` | each is a boundary with its own tests (the control client against a real tmux, the stream against pipes); `towerd`, `loop` and `ui` stay about behaviour | fold them into `towerd` and `transport`, which would mix the daemon with its parts |
| 2 | The dashboard is tower's own Bubble Tea UI from step 2 on; no fzf | the step-4 dashboard is a Bubble Tea column UI anyway; a native list makes live updates, a kept cursor and kill-without-waiting plain model updates instead of fzf reload round trips, helper processes and hide files, and drops fzf as a requirement on every host | an fzf picker in step 2 replaced in step 4 (two front ends, the first thrown away) |
| 3 | The fake ssh is its own test binary (`test/scenario/fakessh`), chosen with `TOWER_SSH` | test code stays out of the shipped binary | a hidden `tower _fakessh` subcommand |
| 4 | towerd's local socket serves one call per connection: a request line, a reply line | a call is its own unit of cancellation (the caller closing the connection cancels a long call); a unix connect costs microseconds | multiplexed calls on a persistent connection |
| 5 | `TOWER_HOME` puts config in `$TOWER_HOME/config` and state in `$TOWER_HOME/state` | tests and demos keep everything under one directory | separate overrides per directory |
| 6 | The relay works on raw descriptors with `poll`; one output goroutine polls ssh's stdout pipe, its pty, a wake pipe and an exit pipe; the loop's writes queue under the terminal's mutex and wake it through the pipe | the input copy must know a byte is there before reading it; the output must wait on two sources, the loop's writes and a 50ms deadline at once, which a goroutine blocked in `read` cannot; on macOS closing a pty blocks while a read on it is blocked | `os.File` reads with deadlines and a channel to the output goroutine (it cannot select while blocked in a read); a reader goroutine per source sharing the terminal under a mutex (a blocked terminal then blocks the loop's `Hold`) |
| 7 | The sequence tracker follows only the bytes after the last ESC, CAN or SUB of each read, and skips whole UTF-8 characters | those three bytes leave a terminal's parser in the same state from any state; following every byte cost 70µs per 32 KiB of wide and binary output, which cut a relayed 200 MiB `cat` to 117 MB/s against 221 given the terminal; now 217 | follow every byte; follow only while a write is queued (the state at the write needs what came before) |
| 8 | A relay that ends inside a sequence writes CAN before the loop's queued writes | a session ended in the middle of an OSC (the hand-off's SIGTERM) leaves the terminal's parser inside it, which would swallow the client restore and the next client's first frame | ST (ends strings only); nothing |
| 9 | `Terminate` and `Kill` also stop the relay taking the terminal's input, at once; `Relay` leaves the terminal's modes to the loop; a session ended by a signal exits 128 + the signal | keys typed between a switch and ssh's exit belong to the next client; the loop makes the terminal raw once for all its attaches; the attach's exit is what a shell would report for ssh | stop the input when ssh has exited; `Relay` making the terminal raw and restoring it per session |
| 10 | `ReadUntil` returns the output before the marker and keeps what follows it for `Relay`; the standby markers are `ESC ] 7193 ; tower-standby-ready BEL` and `… ; tower-standby-go BEL` | a marker and tmux's first output can come in one read; a name that says what it is cannot be mistaken for another program's OSC 7193 | drop the output around a marker; `ESC ] 7193 ; ready ST` |
| 11 | The picker's rows are ordered by recency across hosts within three bands (reachable, not reachable, off), not grouped by host | one list ordered like `tmux ls` on one server; the most recent session is first wherever it runs | rows grouped per host, hosts by recency |
| 12 | `-` and `.` are `⏎` on the previous and current session's row, not cursor moves | one key goes back, as `prefix L` does; `.` in the loop's picker re-attaches to where it was | move the cursor there and wait for `⏎` |
| 13 | A query change puts the cursor on the first match; live updates keep it on its row by key (host id, instance, session id, window id) | fzf's habit while typing, and a row never changes under the cursor while you read | a "moved" flag deciding between top and identity |
| 14 | `⏎` reads a fresh view (one local call) and resolves the row's ids in it before acting | a row killed, renamed or from a restarted server since it was drawn is caught even with live updates off; it costs well under a millisecond | resolve against the last view the model holds |
| 15 | A kill's hide clears only when a view read started after the answer lands | a read in flight when the answer came may predate the kill and would bring the row back for a frame | clear the hide on the answer |
| 16 | One preview capture in flight; an answer for a row no longer selected is dropped and the selected row's asked for; no capture on view changes | holding `↓` sends one request per answer, and previews travel only for the selected row | a capture per cursor move, or a timed debounce |
| 17 | Inside tmux the dashboard gives Bubble Tea a true-colour profile instead of letting it detect one | detection runs `tmux info` through `PATH` on every popup start (60–80ms through a version manager's shim); tmux maps RGB to the outer terminal's colours | Bubble Tea's detection; 256 colours |
| 18 | The renderer runs at 120 fps, Bubble Tea's maximum | Bubble Tea flushes frames on a ticker, so the first frame and each key's echo wait up to one tick (8.3ms instead of 16.7ms) | the default 60 fps; a renderer of our own |
| 19 | `tower` typed inside tmux passes `TOWER_*` (with the resolved tmux binary and machine key) as assignments in the popup's shell command and runs the binary by path | `display-popup -e` needs tmux 3.3 and tower supports 3.2; the popup starts without a shim or `ioreg` | `display-popup -e`; relying on the server's environment |
| 20 | With `TOWER_TMUX` unset, `tower` inside tmux takes its server from `$TMUX`: `-L <name>` in tmux's socket directory, else `-S <path>` | a `tower` typed in a `tmux -L work` session reaches that server's towerd, not the default one | require `TOWER_TMUX` |
| 21 | The dashboard popup is 80% × 80% (`ui.PopupSize`; 90% × 85% since 108) | room for the preview while the session stays visible around it | full size |
| 22 | `status` calls do not count as activity for towerd's idle exit | ensure, `tower status` and monitoring poll `status`; counting them would keep an idle towerd alive forever | count every call; a separate ping call for ensure |
| 23 | A link is `up` only once the host's first state is in, not at the hello | the hello and the first state are separate messages; marking up at the hello showed the host empty for a moment (LC01) | put the first state inside the hello |
| 24 | `_tower` is made with `tmux -N new-session` | the probe and the creation are two commands; a server that exits between them must not be started again by towerd | create it through the control client (needs a session to attach to first) |
| 25 | The keeper checks its towerd every 250ms | a crashed towerd's `_tower` and server go within a quarter second; `kill(pid, 0)` costs nothing | every second, as first written |
| 26 | A key is put back on stop only if `list-keys` still prints exactly the line towerd bound (recorded in `keys.json`) | a user's own binding that runs tower (`TOWER_CLIENT` in it) must never be taken for towerd's | match on `TOWER_CLIENT` or `tower last` in the command |
| 27 | `act new` on a host known to have no server gets a 15s deadline at the first towerd | starting the server runs the user's config (seconds with a plugin manager); the dashboard should not need to know | every caller passes a long deadline for `new` |
| 28 | The home's hosts are reached through a `Transport` interface (dial, probe, master exit, attach argv, sweep); ssh in production | towerd's unit tests join daemons in one process over their real sockets, so the home's logic is tested without ssh or the scenario harness | test the home only through the scenario suite |
| 29 | A towerd started by the attach shim is remote-only (`--bridged`) | an attach (or a standby) on a remote must never turn that machine into a home that dials its own host list | start it as a home like any other caller |
| 30 | A duplicate alias keeps retrying with backoff and lists no sessions | if the alias that linked goes away the other takes over; listing both would show every session twice (S03) | drop the duplicate for good |
| 31 | `prepare` creates a loop it does not know | a loop's first prepare can race its first beat, and the suite prepares for loops it drives itself | refuse until the first beat |
| 32 | The fake ssh rides an existing master whatever the session's `ControlMaster` (`no` only declines to make one) | that is ssh's behaviour, and the home's probe depends on it: riding the master tells a dead master (no answer) from a wedged towerd on a healthy one | keep the fake's own connection for `ControlMaster=no`, which made every probe answer and a half-open master look healthy |
| 33 | A paced run that sends nothing (an unchanged body, a link not yet up) costs no token | otherwise the kicks a link gets while connecting empty its bucket and its first real view waits 150ms (found by V06) | a token per run, as a plain token bucket |
| 34 | The scenario suite drives towerd's loop calls with a scripted `FakeLoop` (beats, prepare, the real shim in a terminal, wait-switch, held, after) | towerd's side of hand-offs, relearning and upgrades can be tested before the attach loop exists, and stays testable without its UI | wait for the loop to test any of it |
| 35 | The view's loop entry carries `Seen`: the home has seen the current attach's client | the loop's fallback frame release waits for it ("150ms after the home sees the new client"); `watch` wakes on the change, so the loop needs no other call | a separate `bound` call, or comparing generations in the view |
| 36 | A note for the next client ("tower: C:charlie ended; now on B:spare", why a hand-off came back) rides the attach: the shim's `--note` or the go line's `note` adds `display-message -d 4000` to the attach's command list | the protocol puts it in the new client's status line, and the loop alone knows when that client attaches, on any host; no extra round trip | the home running `display-message` on the client's host once it binds it (an extra request, after the fact) |
| 37 | Ending a relayed client for a switch is `Terminate` plus `Abandon`: the relay stops at once and ssh is reaped in the background | waiting for ssh to exit put its teardown (a second, behind a delayed link) on the hand-off's critical path: eager hand-offs away from a remote took 1.0–1.3s at 50–400ms RTT, now 34–218ms | wait for ssh's exit, as before |
| 38 | A remote attach whose host the view shows stalled or down before the home has seen its client is given up: a hand-off goes back where the terminal was with the reason in the status line; otherwise the loop retries that target as after a lost connection (pause, a new link ends it early, ctrl-c the picker) | a switch to a host that stalls as it is switched to would otherwise hang behind ssh's alive window (15s) with the frame held; a working client whose host froze before its state reached the home is cut too, but the retry puts it back as soon as the host is | "before the session drew anything" (the fake ssh's hosts without a pty draw on a stalled link, so it never fired there); the picker after a first attach given up (LC04 lost its client for good) |
| 39 | The loop reserves the standby of the host it is preparing; the refresh never drops it, `take` decides | the prepare itself changes the home's offers (the target becomes the current host), and the refresh it set off dropped the very standby the attach was about to take | take the standby before the prepare (its key is only known after) |
| 40 | The home offers a standby to the host a loop just left when that loop is at the picker | after an exit to the picker the loop is attached nowhere; without it the host left had none for the next pick (LS09) | clear the loop's current target on the picker (it is still its previous for `-`) |
| 41 | The standby shim writes its markers on stdout, where an attach's output goes; a relay session's `Close` closes the pty before waiting | on a real host both are the pty; with ssh's pty elsewhere (the fake ssh's host without one) the markers stayed on the loop's pty unread, and a standby killed with unread output never finished exiting on macOS | read markers from the pty too |
| 42 | The loop honours `TOWER_EAGER=0` by not calling wait-switch | with nobody waiting the home leaves ending the client to the dashboard, as the protocol's fallback; the flag then works from the loop's environment as well as the home's | read it only in the home |
| 43 | The relay's client restore no longer clears the screen, and the loop writes it only for a session that drew something | it is now also written after a lost connection (255), which may never have entered the alternate screen; there the clear and `ESC[r` would wipe and home the shell's screen; entering the alternate screen with 1049 clears it anyway | keep the clear and write it only for hand-offs |
| 44 | The picker ranks matches: the name, a prefix of it, inside it (word starts first, then earlier), `host name` without spaces, then scattered characters (tighter first); ties in recency order | a query must reach the session it names (`s50` is not `s150`) and `⏎` takes the top row, as fzf users expect | match only (rows in recency order), which made the suite rename sessions so no query matched two |
| 45 | The UI draws with plain SGR sequences (`x/ansi`), not Lip Gloss | Lip Gloss's package-level writer detects a colour profile at init, which inside tmux runs `tmux info` through `PATH` in every tower process with a terminal on stdout (5ms with the binary, 60–80ms through a shim); Bubble Tea's renderer maps true colour to the terminal's profile anyway | keep Lip Gloss and set `COLORTERM`/`NO_COLOR` for our processes (cannot reach init, and would change colours) |
| 46 | A new session on a host with no server gets a 15s deadline in the dashboard too | towerd allows 15s for the user's config; a dashboard giving up at 5s would report a failure for a session that is then made | the 5s dashboard deadline |
| 47 | rename-session and rename-window put `--` before the name | a name starting with `-` (S19) was read as a flag | quote it (tmux's parser still sees a flag) |
| 48 | LC07 detects any tmux call that bypasses the resolved binary with a logging shim under a `mise/shims` directory first on `PATH` | the machine has no real tmux shim to measure through; mise cannot name a binary for it, so tower must pass it over, and any call through it is a regression | compare timings against a real shim |
| 49 | A control-mode block ends only at the `%end` or `%error` carrying its `%begin`'s time, number and flags | tmux does not escape command output: a capture of a pane showing control-mode output holds `%end …` lines that ended the reply early and opened a fake block, after which every reply went to the wrong command | escape or filter captures (tmux has no way to) |
| 50 | `$XDG_RUNTIME_DIR` holds the run dir only without `TOWER_HOME`, as `tower/<machine key>` | it is per user; several machines simulated on one box under their own `TOWER_HOME` (the scenario suite) shared one socket, lock and control-socket dir there | key it by TOWER_HOME's hash too |
| 51 | ctrl-c between attaches gives the picker: SIGINT cancels the loop's wait (first prepare, `after`), the ctrl-c byte while reconnecting with the terminal raw | Go's default SIGINT killed the loop: no `loop-bye`, the hold and the terminal's modes left, the pid file behind; the protocol's reconnect row gives ctrl-c the picker | exit on ctrl-c (cleanly) |
| 52 | A loop call that finds no towerd starts one and beats: at once for the user's own steps (prepare, after, held, the picker), after 10s for background calls | a towerd that died left the loop failing for ever; the background grace keeps a home being restarted (an upgrade, V07's restart) from being raced | restart at once from every call |
| 53 | Standby sessions start outside the set's lock | a refresh held it across a pty, ssh's fork and exec, and a remote hand-off's take waited | a goroutine per start under the lock |
| 54 | `proto.ParseClient` is the one TOWER_CLIENT parser for the dashboard and the CLI; towerd's own `parseClient` should switch to it | three copies of one format | keep each |
| 55 | The dashboard dates a request's deadline with `stream.Now` | towerd checks deadlines in that clock (`TOWER_TEST_SKEW` moves it); the wall clock made a skewed host's requests expire early or late | the wall clock |
| 56 | The loop names its local client by its own tty to detach it: one tmux run | a client's name is its tty and a local client runs on the loop's terminal; listing clients first cost a second tmux process on the hand-off's path | towerd's control client (protocol.md's step 5), which needs a towerd op |
| 57 | The scenario suite finds processes by their exact argv and environment: /proc on Linux, kern.procargs2 on macOS | `ps -E` is macOS only and its output joins the environment with spaces | parse `ps` on each |
| 58 | The install root on a host is the shell word `"${TOWER_INSTALL_DIR:-<the home's root>}"` | the home's own `TOWER_INSTALL_DIR` moves every host's root (real-host checks), a host's own moves only its own (each simulated machine in the suite), and the default costs nothing | a root fixed by the home alone, which put every simulated host of a world in one directory |
| 59 | A missing build is found by the stream's own exit 127, not by a version check before it | a host that has the build streams at once with no extra round trip; the cost is paid once per host and version | `<path> version` over ssh before every connect |
| 60 | A 127 right after an install fails the host instead of installing again | an install that does not take (a full disk, a noexec root) would otherwise loop upload after upload | retry the install at the backoff cap |
| 61 | `StatusInstalling` (`installing`) is its own host status while the build uploads | dashboards and `prepare` see why the host is not up yet, and `prepare` keeps waiting for it as for `connecting` | `connecting` with the reason only |
| 62 | The dist cache is checked against its `checksums.txt` and its archive extracted afresh on every install | a rebuilt development archive keeps its name; a cache file changed since the download is refused | trust a binary extracted once |
| 63 | `TOWER_DIST_DIR` is the parent of the version directories (default `~/.cache/tower/dist`); `TOWER_RELEASE_URL` the base of `v<version>/<asset>` | one override covers every version, and tests serve a release from an httptest server | a variable naming one version's directory |
| 64 | The suite simulates another platform with a `uname` shim on the host's PATH, serving archives that hold the real build | the simulated host is this machine, so the installed build must run here; the install logic never inspects the binary | cross-compiled archives the fake host could not run |
| 65 | A host in `hosts.toml` may set `home`, which every remote tower command gets as `TOWER_HOME` | the real-host tests must keep a host's tower state under `~/.cache/tower-test/harness/` (the user's own tower and demo live beside it); ssh cannot pass environment without the server's `AcceptEnv` | a wrapper script as the pinned binary (no help for install on connect, which runs the versioned path) |
| 66 | The loop sends each waiting standby an empty line every 2s; a shim that hears nothing for 30s exits (`TOWER_STANDBY_SILENCE`) | over Tailscale SSH a session whose client went away keeps its pty, so the shim never got a hang-up: R02 left one on `alpha`, and every loop exit or reconnect would have left one for 12h | the remote towerd ending its homes' standbys (it cannot tell a loop gone from a home asleep); a shorter life (a standby used after hours would be gone) |
| 67 | Every remote line runs as `sh -c '<line>'`, quoted with `'"'"'` rather than `'\\''` | ssh hands it to the user's login shell, and tower's lines are POSIX: fish rejects `${…}`, and reads a backslash before a quote as an escape even inside single quotes | require a POSIX login shell |
| 68 | The install path has a platform directory, `<root>/<v>/<uname -sm>/tower` | hosts of two architectures sharing one home directory each need their own build | treat an exec-format failure as a missing build (two such hosts would overwrite each other) |
| 69 | An upload goes in place only if every byte arrived and it says it is the version it is installed as | an upload cut short was installed and never repaired; a binary replaced on the home since towerd started was installed under the old version | check only the exit status of `cat` |
| 70 | `current` moves only to a newer version (`sort -V`) | a home of an older version installing there downgraded the host's tower | always swap |
| 71 | A dist archive is verified against its own `<archive>.sha256` (downloads) or `checksums.txt` (`mise run dist`), and refused with neither | a download overwrote the cache's checksums.txt, and an unlisted archive ran unverified | one checksums.txt per version |
| 72 | Only a successful install counts toward "did not take"; a failed install is retried at the backoff cap | a failed install was retried every other cap, under a false reason | count every attempt |
| 73 | A dirty tree's version carries a hash of its changes (`-dev+<sha>.dirty.<hash>`) | every rebuild of edited code had one version, so hosts kept running the first one | a build id compared in the hello |
| 74 | A missing build exits 127 by an explicit check before exec | macOS's sh exits 126 for exec of a missing file, which the link took for another failure | rely on exec's status |
| 75 | The new client's note travels in `prepare` (shim argument and go line) | the loop appended it to the remote line, which now sits inside `sh -c` | keep editing argv in the loop |
| 76 | Git state and zoxide directories come from a refresher of their own (`internal/dirs`), joined in when a state or a view is built | the watch's re-read runs on every tmux change and stays one control-mode batch; a git status is a process start (about 5ms of CPU), and a stat on a dead NFS server blocks | run git in the re-read; have the dashboard ask for it |
| 77 | A repo's root and linked worktree come from the file system (`.git`, its `gitdir`, that dir's `commondir`); one `git status --porcelain=v2 --branch` per repo gives the branch and the dirt | no process for a directory outside any repo (most zoxide entries); sessions in one repo share one status | `git rev-parse` per directory before the status; reading `HEAD` for the branch (a reftable repo keeps none there) |
| 78 | git runs with `--no-optional-locks` and `--ignore-submodules=dirty`, untracked files as the repo's own setting says | it never takes `index.lock` from under the user's own git; a status inside every submodule multiplies the cost; a huge repo can turn the untracked scan off itself | `-uno` (a new file would not count), git's default submodule handling |
| 79 | The sessions' repos are refreshed every 60s and a new session's at once; zoxide's repos only when a dashboard looks (a `view` call, at most every 10s per towerd; a repo asked within 2s is left alone) | only an open dashboard shows the zoxide dirs; on a host with 40 sessions and 140 repos followed a look costs 0.75–1s of CPU, the periodic refresh 0.2–0.3s (0.4–0.6% of a core) | refresh everything every minute (1.2% of a core with nobody looking); a file system watcher per repo (platform code, watch limits, and NFS sends no events) |
| 80 | A `look` stream message: a dashboard's towerd tells its homes and its home's hosts, a home passes a host's look to its other hosts, nobody passes on a home's | every host a dashboard can show refreshes as it opens, without the dashboard asking each; no look goes back where it came from, and the rate limit bounds a storm of reads | a flag on `view` set by the dashboard (both sides to change); remotes refreshing only on their timers (a minute stale) |
| 81 | Network mounts come from the mount table: `/proc/self/mounts` on Linux, `getfsstat(MNT_NOWAIT)` on macOS; `autofs`, `fuse` and every `fuse.<name>` but known local ones count as network | neither read waits on a server; `getfsstat` is what `mount` prints, without a process start; a FUSE mount taken for a network one only loses its branch | run `mount` and parse it; stat with a timeout (a blocked stat holds its thread for ever) |
| 82 | Zoxide dirs are capped at 100 git roots and 100 others, in frecency order | states and views are sent whole: 200 dirs are 12 KB of each; the dashboard lists roots by default, so the plain long tail is cut first | the whole database (500 entries, about 30 KB on every push); one cap of 200 (a rarely used repo lost behind plain dirs) |
| 83 | A host leaves its sessions' directories out of its dirs | it knows its own home, so it compares `~/x` with `/home/u/x`; a dashboard does not know a remote's home; a session made in a dir leaves the list in the state sent with the answer | the dashboard filters (the view would need each host's home) |
| 84 | `new` expands `~` on the target host, passes `-c` with `#` doubled, refuses a directory that is gone (unless on a network mount), and starts a window with no directory in its session's (`-c '#{session_path}'`) | tmux expands no `~` and does expand formats in `-c`, and starts in the home without a word when it cannot enter a directory; dashboards spell dirs with `~` | expand on the dashboard (it does not know a remote's home); a window in the home, as before |
| 85 | `capture` answers with its window's panes, read in the same control-mode batch; `panes` lists a session's or a window's alone; pane paths use `~` for the host's home or its resolved path | the layout preview needs both at once, in one round trip; tmux reports a pane's directory with symlinks resolved | a `panes` request after every capture; absolute paths |
| 86 | The popup and the loop's picker open in the finder; `esc` there closes the dashboard (`tower dash`: the last target), `^c` clears then closes, `^l` shows the row in the columns; `f` from the columns opens it with `esc` back | typing a name and ⏎ is the habit of the fzf picker it replaces and of the step-2 picker; the finder searches every host at once, which a column search does not | open in the columns (the prototype), with type-to-filter only after `/` or `f` |
| 87 | The finder lists git-root zoxide dirs after reachable hosts' sessions by default; `^g` switches between git roots and every entry, one setting for the finder and the columns | the fzf picker listed git roots under the sessions, so typing a repo's name and ⏎ made its session; that habit must survive the finder becoming the front door | dirs only after `^g` in the finder (the prototype) |
| 88 | `-` and `.` (with an empty query) select the previous and current session; ⏎ goes there | Atlas's meaning, the same in the finder and the columns; the step-2 picker's ⏎-at-once left no way to look first | ⏎ at once on `-` and `.` |
| 89 | Kill asks y/n with what is at stake; `panes` is asked as the question opens and its running commands added when it answers; kill-without-waiting starts at `y` | a kill cannot be undone and the question costs one key; asking towerd first would delay the question by a round trip | kill at once (the picker); wait for `panes` before asking |
| 90 | The UI draws on a cell canvas of its own (graphemes, widths, styles) and turns it into SGR lines; captures are parsed into cells | columns side by side, overlays (help, the add-host picker), wide characters and match highlights need cells; decision 45 rules out Lip Gloss | splice styled strings per line; ultraviolet's buffer (an indirect dependency, its API unpinned) |
| 91 | Finder scoring: a word scores against host, session and windows (substring above scattered; the whole name, its start, a word start, nearer the front); a session ranks by the sum; ties keep recency; a window row scores its words plus the session's and takes the cursor only when strictly better | words in any order and tmux-style targets need per-word scores; recency for ties keeps the most used first among equal matches | decision 44's tiers on `host name` (one query string); shorter names first on ties |
| 92 | `internal/hosts` holds the host list's edits, naming rules, ssh aliases and checks; `tower host` and the dashboard both use it, so the CLI now cleans names (`:` and spaces as `-`) and keeps an alias's name for its own host | one set of rules and one check-and-install path; the dashboard must not run checks the CLI does not | keep the CLI's code in `cmd/tower` and copy it into the dashboard |
| 93 | The dashboard runs a new host's checks in its own process within 15s and saves the host after them, failed or not, as `tower host add`; closing it mid-check adds nothing | the same order as the CLI; saving first would have the home connect and install while the checks run | save first and show the home's own connect as the checks |
| 94 | ⏎ on a host (or its row) that is down or failed asks towerd for `netchange` (every down host retries now); a stalled host is refused as before | towerd has no call to retry one host; `netchange` retries only hosts that are down, so healthy links are untouched | a per-host retry call in towerd (not built) |
| 95 | Errors stay in the footer until the next key, outcomes for 2.4s, what is in flight until its outcome | an error the user looked away from must still be there; outcomes are noise after a moment | every message for 2.4s (the prototype) |
| 96 | Captures are kept (64) and shown at once when the selection comes back, while a fresh one is asked for | moving back and forth through windows shows something at once, still one capture in flight | drop an answer for a row no longer selected (step 2) |
